# 要件定義書

## 2. 用語

| 用語 | 定義 |
| --- | --- |
| 備品 | 本アプリで写真を記録する管理対象物 |
| 備品シール | 備品番号が記載され、備品に貼付されたシール |
| 備品番号 | 備品を識別するため、備品シールから読み取って利用者が確定する文字列 |
| シール写真 | 備品番号を読み取るために撮影した備品シールの写真 |
| 全体写真 | 備品番号確定後に撮影する備品全体の写真 |
| OCR | シール写真に含まれる文字を認識する処理 |
| 備品番号候補 | OCR結果から備品番号として利用者へ提示する文字列 |
| 撮影ジョブ | 1件の備品について、確定した備品番号、シール写真、全体写真、および処理状態をひとまとまりとして扱う管理単位 |
| 完成済みジョブ | 備品番号が確定し、シール写真、全体写真、および復旧に必要な情報が端末内へ保存された撮影ジョブ |
| 未完成ジョブ | 完成済みジョブの条件を満たしていない撮影ジョブ |
| 未送信ジョブ | Google Driveへの保存が完了していない撮影ジョブ |
| アップロードキュー | Google Driveへの保存を待つ完成済みジョブの集合 |
| 送信済み | 必要な写真がGoogle Driveへ保存されたことを確認できた状態 |

## 3. 目的

### 3.1 解決したい問題

備品シールから備品番号を読み取り、シール写真と備品全体写真を対応付けて記録し、
通信状況に左右されず撮影作業を継続できるようにする。

撮影済みデータをGoogle Driveへ保存し、備品番号と写真の対応関係を維持する。

### 3.2 想定利用者

備品の写真をスマートフォンで撮影し、備品番号を確認して記録する作業者を想定する。

利用者の所属、役割、IT習熟度、および利用人数は未確定とする。

### 3.3 対象範囲

- 備品シールの撮影
- OCRによる文字認識と備品番号候補の抽出
- 利用者によるOCR結果の確認および手修正
- 備品番号確定後の備品全体写真の撮影
- 備品番号、シール写真、および全体写真の一組での管理
- 撮影データの端末内保存
- 未送信データの保持と復旧
- Google認証
- Google Driveへの保存
- 送信失敗時の再送

### 3.4 対象外

- 備品台帳そのものの作成、編集、および検索
- 備品の貸出、返却、棚卸し結果などの業務管理
- Google Drive以外のクラウドサービスへの保存
- iOSを初期開発の優先対象とすること

対象外の範囲を将来追加するかどうかは、この初期版では決定しない。

## 4. 基本業務フロー

1. 利用者がアプリを起動する。
2. アプリが完成済みの未送信ジョブを復旧する。
3. 利用者が備品シールを撮影する。
4. アプリがOCRを実行し、備品番号候補を抽出する。
5. 利用者が候補を確認し、必要に応じて手修正する。
6. 利用者が備品番号を確定する。
7. 利用者が備品全体を撮影する。
8. アプリが備品番号、シール写真、および全体写真を1件の撮影ジョブとして端末内へ保存する。
9. アプリが完成済みジョブをアップロードキューへ登録する。
10. アプリがGoogle認証と通信状態を確認し、送信可能なジョブをGoogle Driveへ保存する。
11. 保存に失敗したジョブは、再送可能な状態で端末内に保持する。

アップロードを開始する具体的な方法は未確定とする。

## 5. 機能要件

### 5.1 アプリ起動・状態復旧

#### FR-001 アプリ起動時の未送信ジョブ復旧

- 要件：アプリは、起動時に端末内へ保存されている完成済みの未送信ジョブを復旧しなければならない。
- 完了条件：アプリを終了して再起動した後も、終了前に保存済みだった完成済みの未送信ジョブを確認でき、送信対象として扱える。
- 状態：確定
- 備考：未完成ジョブをどこまで復旧するかは未確定とする。

### 5.2 シール写真撮影

#### FR-010 シール写真の撮影

- 要件：利用者は、備品番号を読み取る対象となる備品シールを撮影できなければならない。
- 完了条件：利用者が撮影操作を行い、OCRの対象となるシール写真を確認できる。
- 状態：確定
- 備考：写真の形式、解像度、および圧縮率は未確定とする。

### 5.3 OCR

#### FR-020 シール写真のOCR実行

- 要件：アプリは、撮影したシール写真に対してOCRを実行しなければならない。
- 完了条件：シール写真の撮影後、認識された文字列または認識できなかったことを確認できる。
- 状態：確定
- 備考：認識精度および処理時間の目標値は未確定とする。

### 5.4 備品番号候補抽出

#### FR-030 備品番号候補の抽出

- 要件：アプリは、OCR結果から備品番号候補を抽出し、利用者へ提示しなければならない。
- 完了条件：OCR結果が得られたとき、利用者が備品番号候補を確認できる。
- 状態：確定
- 備考：抽出規則は、備品番号の形式が決定した後に確定する。

### 5.5 OCR結果の確認・手修正

#### FR-040 OCR結果の確認と手修正

- 要件：利用者は、提示された備品番号候補を確認し、誤りがある場合は確定前に手修正できなければならない。
- 完了条件：利用者が候補を確認でき、編集した文字列を備品番号の確定対象として使用できる。
- 状態：確定
- 備考：OCRで候補を得られない場合の具体的な入力手順は未確定とする。

### 5.6 備品番号確定

#### FR-050 備品番号の確定

- 要件：アプリは、利用者による確認または手修正を経た文字列を備品番号として確定できなければならない。
- 完了条件：利用者が確定操作を行った後、その備品番号が対象の撮影ジョブに対応付けられていることを確認できる。
- 状態：確定
- 備考：備品番号の形式と入力検証規則は未確定とする。

### 5.7 全体写真撮影

#### FR-060 備品全体写真の撮影

- 要件：利用者は、備品番号の確定後に、その備品の全体写真を撮影できなければならない。
- 完了条件：備品番号が確定している撮影手順で全体写真を撮影し、撮影結果を確認できる。

### 5.8 撮影ジョブ管理

#### FR-070 写真と備品番号の一組での管理

- 要件：アプリは、1件の備品について、確定した備品番号、シール写真、および全体写真を1件の撮影ジョブとして管理しなければならない。
- 完了条件：異なる備品の写真が混在せず、対象の備品番号から同じジョブに属する2枚の写真を識別できる。
- 状態：確定
- 備考：同じ備品番号が存在する場合および再撮影時の処理は未確定とする。

#### FR-071 撮影ジョブの完成判定

- 要件：アプリは、備品番号が確定し、シール写真、全体写真、および復旧に必要な情報が端末内へ保存された場合に限り、撮影ジョブを完成済みとして扱わなければならない。
- 完了条件：いずれかの条件を満たさないジョブは完成済みまたはアップロード対象として扱われず、すべての条件を満たすジョブだけが完成済みになる。

### 5.10 アップロードキュー

## 6. 異常時・中断時の要件

### 6.1 アプリ異常終了

- 完成済みの未送信ジョブは、アプリの異常終了後も失われてはならない。
- 送信処理中に終了したジョブは、送信成功を確認できない限り送信済みとして扱ってはならない。
- 未完成ジョブの復旧範囲は未確定とする。

### 6.2 端末再起動

- 完成済みの未送信ジョブは、端末再起動後も復旧できなければならない。
- 再起動前に送信中だったジョブの扱いは、保存済みの送信結果を確認して判断できなければならない。

### 6.3 ネットワーク切断

- ネットワーク切断によって未送信ジョブおよび写真が失われてはならない。
- 通信できない間は未送信状態を維持し、再送可能でなければならない。

### 6.4 Google認証エラー

- 認証できない場合、アップロードを成功として扱ってはならない。
- 認証エラーが発生しても、撮影済みデータを保持しなければならない。
- 利用者が必要な対応を判断できるエラーを示さなければならない。

### 6.5 Google Drive APIエラー

- Google Driveへの保存結果を確認できない場合、対象ジョブを無条件に送信済みとして扱ってはならない。
- 送信に失敗したデータは削除せず、再送可能な状態で保持しなければならない。
- 一部の写真だけが保存された場合の処理は未確定とする。

### 6.6 カメラまたはOCRの失敗

- カメラによる撮影が完了しなかった場合、その写真を撮影済みとして扱ってはならない。
- OCRで候補を得られなかった場合、利用者が失敗を確認できなければならない。
- OCR失敗時の手入力および撮り直しの具体的な操作は未確定とする。

### 6.7 端末内保存失敗

- 必要な撮影データの端末内保存に失敗した場合、対象ジョブを完成済みとして扱ってはならない。
- 利用者が保存失敗と必要な対応を確認できなければならない。

## 8. データ要件

### 8.1 撮影ジョブ

- 1件の撮影ジョブは、1件の備品に関するデータを表さなければならない。
- 撮影ジョブは、確定した備品番号、シール写真、全体写真、および処理状態の対応関係を保持しなければならない。
- 撮影ジョブは、ファイル名だけに依存せず識別できなければならない。
- 内部的な識別子の形式は未確定とする。

### 8.2 シール写真

- シール写真は、対象の撮影ジョブと対応付けられなければならない。
- OCRに使用した写真を、アップロード前に端末内へ保存しなければならない。
- 保存形式、解像度、および圧縮率は未確定とする。

### 8.3 全体写真

- 全体写真は、備品番号確定後に撮影され、対象の撮影ジョブと対応付けられなければならない。
- 全体写真を、アップロード前に端末内へ保存しなければならない。
- 保存形式、解像度、および圧縮率は未確定とする。

### 8.4 送信状態

- 撮影ジョブごとに、Google Driveへの送信結果を識別できる情報を保持しなければならない。
- 送信成功が確認されていないジョブを送信済みとして記録してはならない。
- 送信失敗後に再送対象であることを識別できなければならない。
- 状態の名称、粒度、一部送信成功時の表現、および更新履歴の保持要否は未確定とする。

## 9. 権限要件

- アプリは、シール写真および全体写真を撮影するために必要なカメラ利用権限を、利用者の許可に基づいて使用しなければならない。
- カメラ利用権限が許可されていない場合、撮影を成功として扱ってはならない。
- アプリは、Google Driveへの保存に必要な権限を、認証したGoogleアカウントから取得しなければならない。
- Google Driveの権限が不足している場合、アップロードを成功として扱ってはならない。
- 端末内保存に追加の利用者権限が必要かどうかは、対応Androidバージョンと保存対象の決定後に確認する。
- Google Driveで要求する具体的な権限の範囲は未確定とする。

## 10. 制約

- アプリはFlutterおよびDartで開発する。
- 初期開発ではAndroidを優先する。
- 撮影データのクラウド保存先にはGoogle Driveを使用する。
- 撮影処理とアップロード処理は、利用者がアップロード完了を待たず次の撮影へ進めるよう分離する。
- 撮影データは、Google Driveへアップロードする前に端末内へ保存する。
- サービスアカウントの秘密鍵をスマートフォンアプリへ埋め込まない。
- 状態管理方式、ローカル永続データの管理方式、および使用ライブラリは、この文書では決定しない。
